# ScioKrillion

ScioKrillion (formerly SciOly Dive) is a daily Science Olympiad (Division C, 2027 rules) answer game modeled loosely on Krillion: seven events per dive, one prompt each, 25 seconds per prompt. Rarer accepted answers score more and "sink deeper". It runs on Vercel as a Node server (`api/dive.js`, `api/judge.js`) at https://scioly-dive.vercel.app/. The old GitHub Pages address now only redirects there (`pages-redirect/index.html`), carrying each visitor's saved results along once. The static guest build (`node build.mjs --pages`) still exists but is no longer deployed.

## Prompt style (the most important rule)

Every prompt must be a **specialist prompt** written from its event's 2027 Division C rules, so that someone who studies that event does best. For example: "Name a rock or mineral on the 2027 National Rocks and Minerals List", or "Name an ion you are expected to know for Chemistry Lab". General-knowledge prompts were deliberately removed: no "Name a country/bird/car" prompts, no unit or number puzzles. Don't reintroduce them.

- Cite the rules section you drew from in a comment on the answer list.
- Aim for 60+ accepted answers per prompt (the Daily minimum is `MIN_DAILY_ANSWERS` = 60 in `selection.js`). Where the topic allows, aim for hundreds to about a thousand: pull long lists from open data (Disease Ontology, REBASE, Wikipedia lists and categories, Wikidata) with `scripts/sourced-answers.mjs`, and hand-write the rest. Fixed lists (the National Rocks and Minerals List) stay their real size.
- Only include answers you are sure are correct. Respect the rules: for example, Boomilever bans bamboo and commercial plywood.
- Only the 23 official events are used. The trial events (Code Craze, Hydraulics, Junkyard Challenge) are paused (`pausedEvents` in `features.js`).
- Future prompt ideas without answer banks live in `catalog-data/prompt-drafts.md`.

| `coverage.js` | `expandedGroups`: merges a prompt's groups, adds everyday aliases (`aliases` map), and folds groups that share a spelling into one answer. |

| `daily-clock.js` | When each Daily runs: midnight to midnight Pacific time, one day before its day number (`dailyDay`, `dailyStart`, `playDay` for the date shown to players). Shared by the client, server and scripts. |
| `features.js` | Switches: `dailyOnly` (only the Daily is offered), `pausedEvents`, and `featuredDailies` (hand-pinned Dailies by day number). |
| `game.js`, `style.css`, `index.html` | Client UI: canvas ocean scene, round flow, results. |
| `guest-api.js` | Judges answers in the browser for the Pages build. |
| `pages-catalog.mjs` | Pages build only: the game bundle gets a prompt-only catalog, and each prompt’s scored answers become `banks/<hash>.json`, fetched by `loadBank` in `game.js` when a dive starts. Keeps the bundle small however long the lists get. |
| `judge.js`, `api/judge.js` | AI fallback for answers not on a list. The Pages site calls `api/judge.js` on Vercel (URL in `judgeUrl`, `features.js`; empty turns it off). The AI rules valid or invalid and rates an accepted answer Schooler (30), Rare (60) or Deep Cut (85), defaulting to Deep Cut; verdicts are cached under `JUDGMENT_CACHE` in `judge.js` (bump its version when the tiers change so answers are judged again); AI-judged answers are labeled AI-checked and are never the Krillion. Gemini (`GEMINI_API_KEY`, free tier) or Azure OpenAI, set in Vercel's environment variables. |

| `api/dive.js`, `serve.mjs`, `dive-storage.js` | Optional server with the same AI fallback, accounts and global stats. |

## Rarity tiers

The tiers are 10 Plankton, 30 Schooler, 60 Rare, 85 Deep Cut and 100 One in a Krillion. (15 "Too Clever" still exists in `tiers` but is unused.) For a list of n answers:

1. An answer that repeats words from its own prompt ("epidemiology" for "Name an epidemiology term...") is Plankton. Then the prompt's obvious-answer lists set Plankton and Schooler.
2. Unless the list is flagged no-fill, corpus familiarity fills Plankton up to about 1.1·ln n and Schooler up to about 1.6·√n.
3. The Deep Cut share grows with the list (`deepShare` in `answer-bank.js`): about 20% of 60 answers, 35% of 200, 50% of 600 and 60% from 1,500 on. The rest is Rare, chosen by familiarity among words the corpus knows. Answers the corpus does not know stay Deep Cuts, so very long technical lists can run above that share.
4. The One in a Krillion prefers an answer with a fun fact (never a Plankton or Schooler answer), then a Rare answer. A stable hash of the prompt breaks ties.
5. Once a prompt appears in a Daily, its Krillion is locked in `catalog-data/krillion-locks.js` (generated by `npm run lock-krillions`, which locks every Daily through 30 days ahead). A test fails if a lock no longer matches, or if a Daily played so far is unlocked. Locks are only added, never rewritten.

After adding answers, regenerate the sourced lists (they skip spellings a hand-written answer already uses) and then familiarity:

```bash
npm run sourced
pip install wordfreq
npm run familiarity
```

Wikimedia rate-limits automated requests heavily; the script caches downloads (pass a cache directory as its argument) and backs off on HTTP 429.

Unscored answers count as Deep Cuts.

## Keeping Claude usage low

Most upkeep runs without Claude. Spend Claude sessions on writing new prompts and answer lists, which is the only part that needs judgment.

- **Scheduling is automatic.** `.github/workflows/plan-dailies.yml` runs every Monday: `npm run plan-dailies -- 14` pins the next two weeks (each event's least recently used prompt, Krillions with facts preferred, events used in the last two days rested), `npm run lock-krillions` locks them, tests run, and the commit is pushed (Vercel redeploys). Don't pin days by hand unless asked.
- **Review with one command.** `npm run check-prompt -- "<part of the prompt>"` prints size, tiers, Krillion (fact, lock), obvious answers, folded groups, short aliases and samples. Use it instead of writing ad-hoc `node -e` scripts or reading answer files.
- **Don't read generated files.** `familiarity.js`, `sourced-answers.js`, `package-lock.json`, `dist/` and `pages-dist/` are blocked in `.claude/settings.json`; regenerate them with their scripts instead.
- **Prefer data over hand-writing.** Where an open dataset fits a prompt, add a source to `scripts/sourced-answers.mjs` rather than typing answers.
- **Batch prompt writing.** Write several drafts from `catalog-data/prompt-drafts.md` in one session, then run `npm run sourced`, `npm run familiarity`, `npm run lock-krillions` and `npm test` once.
- **Use a smaller model for routine edits.** Fixing a typo, adding aliases or swapping an obvious answer works fine with `/model sonnet` or `/model haiku`; keep the largest model for new prompts.
- **The catalog's size limits the schedule.** With about 55 Daily-worthy prompts at 7 per day, a prompt returns after about a week; each new prompt lengthens the cycle. Events with the fewest prompts repeat soonest, so write for those first.

## Pinning Dailies

The Daily seed is a day number: day N is the calendar date N·86400000 (2026-11-27 is 20784). Dailies through 20785 (Nov 28, 2026) ran midnight to midnight UTC on their date, except that 20785 ended at midnight Pacific starting Nov 28. From 20786 on, every Daily was moved forward a day: Daily N runs midnight to midnight Pacific time on date N − 1 (`dailyDay`, `dailyStart` and `playDay` in `daily-clock.js`, which handles daylight saving time), and the site shows that play date. Day numbers, pins, locks and saved results still use N, so date comments in `featuredDailies` and script output by day number are one day after the play date. Use `dailyDay()` for today, never `Math.floor(Date.now() / 86400000)`. `featuredDailies[day]` lists seven `[event, exact prompt]` pairs in round order, each from a different event. Pinned days so far: 20784–20798 (Nov 27 – Dec 11, 2026; Dec 2 onward planned by `npm run plan-dailies`). Unpinned days rotate through all eligible prompts.

When preparing new days:

- Don't repeat a prompt from recent days.
- Mix event types.
- Check each pinned prompt's Krillion has a fact: `node -e` with `questionFor(day, round, undefined, 'Daily')`.
- `npm run upcoming -- 7` prints upcoming Dailies with their answers.

Don't change a Daily that is already live (today or earlier) unless the user asks. New prompts can carry a `since` day so they don't reshuffle the live rotation.

## Commands

```bash
npm ci
npm test
node build.mjs --pages
npm run build
npm start
```

- `npm test` must pass before pushing. It checks matching, Krillion uniqueness, obvious and fact references, and client/server schedule agreement.
- `node build.mjs --pages` builds the static site into `pages-dist/` (bundle plus one answer file per prompt in `banks/`).
- `npm run build` builds the server version into `dist/`.
- `npm start` serves the server version locally at http://localhost:4173.

Vercel deploys every push to `main`. Pushing to `main` also runs `.github/workflows/pages.yml`, which runs the tests and republishes the redirect page on GitHub Pages. The live site is https://scioly-dive.vercel.app/; https://lightningale23.github.io/scioly-dive/ (any path) forwards there.

## Gotchas

- Don't use apostrophes inside answer lists as `'` in single-quoted JS strings. Use `’` (’), or a double-quoted string. Possessive forms are matched with or without the "s".
- Obvious-answer names must be exact canonical names (the first spelling of a group). Tests fail otherwise. Don't write `a|b` in obvious lists.
- `aliases` in `coverage.js` is a plain object: look keys up with `Object.hasOwn` (an answer named "constructor" once crashed the catalog).
- `question.bank` is a lazy getter. Use `row.size` when you only need the count.
- Canvas tier lines during the sink are drawn relative to the depth marker at 42% of the viewport height. The sinking answer in CSS (`.sinkingGuess`) must stay on that marker, with timings matching `DROP`, `SINK` and `HOLD` in `game.js`.
- Verify UI changes in a browser (Playwright is preinstalled) at desktop and phone widths before pushing.
- The name ScioKrillion was the owner's choice (2026-11-28). Other wording written to the site should be original: don't copy Krillion's text or Science Olympiad's branding or logo.
- Saved data keeps its old `scioly-` names (localStorage keys and the like), so renaming the game never wipes anyone's results or streaks.
